# 整曲缓存

`useSongBuffer` 为 KTV 视频播放器的当前歌曲创建缓存会话，包括视频、原唱和伴奏。
`public/media-buffer-sw.js` 按 1 MiB 分块持续下载到 Cache Storage，并为媒体元素提供
HTTP Range 响应。播放器可以先播，浏览器暂停自身预加载时，后台下载仍然继续。
拖动进度条与后台下载共用缓存和正在进行的分块请求。

- 网络失败按 1～15 秒间隔重试；连续 30 秒未收到数据会重试当前块。
- 缓存包含文件元数据，后台进程重启后可继续下载，完整缓存的文件无需联网读取。
- 页面每 15 秒提醒后台继续下载，避免弱网下载期间因后台进程休眠而停止。
- 切歌、离开或关闭页面会终止旧会话并删除缓存；异常退出留下的缓存超过 24 小时后
  在后续会话中清理。这不是跨歌曲、跨页面的永久离线曲库。
- 仅处理显式生成的 `/__ktv_media__` 地址，不缓存 API、页面或普通 `/songs/` 请求。

需要 HTTPS（localhost 也可）和可用的浏览器存储。普通 HTTP 局域网 / Tailscale IP
地址、禁用存储、磁盘配额不足或注册失败时，会回退为浏览器原生缓冲，并显示提示。
反向代理需要能访问根路径 `/media-buffer-sw.js`，以及 `/songs/` 下的 HEAD 和 Range 请求。
当前歌曲的实际下载速度长期低于播放码率时，仍然可能等待；整曲缓存不会提高网络带宽。

修改后在 `front_end` 运行 `npm run build`。自动验证：

```sh
node --test tests/media-buffer.test.js
```
